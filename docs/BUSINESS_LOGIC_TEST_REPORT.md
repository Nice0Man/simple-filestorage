## ❌ ПРОВАЛЕННЫЕ ТЕСТЫ (5/29)

### Test 1.5: Регистрация нового пользователя
**Статус:** ⚠️ INTERMITTENT FAILURE  
**Ожидалось:** Регистрация возвращает токен  
**Фактически:** `{"error":"Registration failed","message":"Username already exists"}`  
**Причина:** Генерация username с использованием `date +%s` не уникальна при быстром выполнении тестов  
**Приоритет:** LOW  
**Рекомендация:** Использовать `date +%s%N` (с наносекундами) или UUID для генерации уникальных имен

### Test 1.7: Получение информации о пользователе с валидным токеном
**Статус:** ⚠️ INTERMITTENT FAILURE  
**Ожидалось:** Возвращает информацию о пользователе  
**Фактически:** `{"error":"User not found","message":"Invalid or expired token"}`  
**Причина:** Race condition - токен используется до того, как сессия полностью сохранена в БД  
**Приоритет:** MEDIUM  
**Рекомендация:** Добавить задержку или синхронизацию после создания сессии

### Test 3.1: Logout с валидным токеном
**Статус:** ❌ FAIL  
**Ожидалось:** Logout успешен  
**Фактически:** `{"error":"Authentication required","message":"Please provide a valid Bearer token in Authorization header"}`  
**Причина:** Токен `$NEW_TOKEN` пустой, т.к. регистрация в Test 1.5 не удалась  
**Приоритет:** LOW (зависит от исправления Test 1.5)  
**Рекомендация:** Исправить Test 1.5 для обеспечения валидного токена

### Test 3.3: Множественные одновременные логины
**Статус:** ⚠️ INTERMITTENT FAILURE  
**Ожидалось:** Два различных токена для одного пользователя  
**Фактически:** `TOKEN1=, TOKEN2=` (пустые токены)  
**Причина:** Ошибка парсинга токенов из JSON ответа в скрипте тестирования  
**Приоритет:** LOW (проблема в тестовом скрипте, не в API)  
**Рекомендация:** Исправить grep/cut команды для извлечения токенов

### Test 6.2: Невалидный endpoint возвращает 404
**Статус:** ❌ FAIL  
**Ожидалось:** JSON с ошибкой  
**Фактически:** Пустой ответ  
**Причина:** httplib возвращает HTML 404, а не JSON  
**Приоритет:** LOW  
**Рекомендация:** Добавить catch-all handler для возврата JSON 404

## 🔧 ИСПРАВЛЕННЫЕ ПРОБЛЕМЫ

### Проблема 1: Connection Pool не инициализируется
**Было:** Timeout 10 секунд при каждом запросе  
**Причина:** `main.cpp` не читал переменную окружения `CONFIG_PATH`  
**Исправлено:** Добавлен `std::getenv("CONFIG_PATH")` в main.cpp  
**Результат:** ✅ Connection pool инициализируется корректно, запросы обрабатываются за ~170ms

### Проблема 2: Login всегда возвращал "Authentication failed"
**Было:** Все логины проваливались  
**Причина:** Сервер использовал `config.json` вместо `/app/config/config.json`  
**Исправлено:** Исправлен путь к конфигу через переменную окружения  
**Результат:** ✅ Login работает для всех пользователей
